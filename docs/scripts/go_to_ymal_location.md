# GO TO YAML LOCATION (`scripts/go_to_ymal_location.py`)

## PURPOSE
The `go_to_ymal_location.py` script is a utility designed to load a pre-recorded physical location (both joint positions and Cartesian pose) from a YAML configuration file and autonomously move the UR5e robot back to that exact position. This ensures safe, repeatable, and precise positioning of the Portraitron robot arm to calibrated zones (like home, paper pickup, pen grab, or testing zones).

## HOW TO USE IT
Execute the script from the command line, optionally passing arguments to customize the robot's behavior, target location, or movement kinematics.

### Basic Usage
To move the robot to the default `base_test` location:
```bash
python scripts/go_to_ymal_location.py
```

### Specifying a Named Location
To move the robot to a specific named location (e.g., `home_position`), the script will automatically look for `config/locations/home_position.yaml`:
```bash
python scripts/go_to_ymal_location.py --name home_position
```

### Advanced Movement and Options
```bash
python scripts/go_to_ymal_location.py \
    --name pickup_zone \
    --speed 0.5 \
    --accel 0.2 \
    --movel \
    --yes
```

### Available Arguments
* `--name`: (Optional) Name of the location to load from `config/locations/{name}.yaml`. Defaults to `base_test`.
* `--config`: (Optional) Direct path to a custom config YAML file. Overrides the `--name` argument.
* `--robot-ip`: (Optional) The IP address of the UR5e robot. Overrides the IP stored in the YAML config.
* `--speed`: (Optional) Movement speed limit. Units: `rad/s` for `moveJ` (joint space) and `m/s` for `moveL` (Cartesian). Default: `0.2`.
* `--accel`: (Optional) Movement acceleration limit. Units: `rad/s^2` for `moveJ` and `m/s^2` for `moveL`. Default: `0.1`.
* `--movel`: (Optional) Flag to force the robot to use a linear Cartesian movement (`moveL`) instead of the default joint-space movement (`moveJ`). Requires Cartesian `pose` data in the YAML file.
* `--yes`: (Optional) Skip the user safety confirmation prompt and execute the movement immediately.

## CONFIG FILES
This script actively reads from YAML files, typically stored in the `config/locations/` directory. 

A standard location config file (e.g., `config/locations/base_test.yaml`) should be structured as follows:

```yaml
robot_ip: "192.168.57.101"
joints: [1.57, -1.57, 1.57, -1.57, -1.57, 0.0]
pose: [0.3, 0.4, 0.2, 3.14, 0.0, 0.0]
```
* **`robot_ip`**: (Optional) The last known IP address of the robot during the recording of this position.
* **`joints`**: (Required for `moveJ`) Array of 6 float values representing the individual rotational angles (in radians) of the UR5e robot's 6 joints.
* **`pose`**: (Required for `--movel`) Array of 6 float values representing the Cartesian coordinates `[X, Y, Z, Rx, Ry, Rz]`, where distances are in meters and rotations are in radians.

*(Note: These files are typically generated by the companion script `scripts/record_base_test_location.py`.)*

## INNER WORKINGS
1. **Argument Parsing and Path Resolution:** Uses `argparse` to extract CLI arguments. If `--config` is not explicitly provided, it resolves the file path to `config/locations/<name>.yaml`.
2. **YAML Data Extraction:** Opens the target YAML file and parses it using `yaml.safe_load()`. It attempts to extract the `joints`, `pose`, and `robot_ip` parameters.
3. **Validation:** Checks if the required target coordinates exist depending on the movement mode:
   * If `--movel` is passed, the script verifies that the `pose` array exists.
   * If not (default), it verifies the `joints` array exists.
4. **Safety Gate:** Unless the `--yes` flag is invoked, the script prompts the user via the CLI to confirm physical movement, warning about the target IP and movement type.
5. **Robot Control Interface:** Connects to the UR5e robot via the `ur_rtde` (Real-Time Data Exchange) Python library using `rtde_control.RTDEControlInterface(ip)`.
6. **Execution:** 
   * Sends a `moveL(pose, speed, accel)` command if Cartesian linear motion is requested.
   * Sends a `moveJ(joints, speed, accel)` command if joint space motion is used (which is mathematically safer and avoids getting stuck on kinematic singularities).
7. **Clean Disconnect:** Ensures the `rtde_c` connection is cleanly severed in a `finally` block to prevent lingering network issues, regardless of movement success or failure.
